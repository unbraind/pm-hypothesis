# Investigation records and invariants

The package uses public pm SDK APIs for schema, settings, native items, parent links, comments, complete-corpus certification and journaled conditional mutation. There is no private store, Git subprocess or diagnostic executor.

## Records

`open` creates a native Question or attaches to a native Question/Issue. Default SDK trackers omit Question/Test types, so `open` registers those types and two optional string fields through the schema SDK. Existing incompatible fields refuse.

`hypothesis_state` is the authoritative version-1 envelope on the investigation: monotonic revision, hypotheses with exact equality predictions, original observations with current admission, and an optional revision-bound conclusion. One complete item read supplies the entire logical snapshot. The matrix is never persisted, so withdrawal cannot leave stale cached eliminations.

Linked Question hypotheses and linked Test observations hold immutable `hypothesis_record` source envelopes. Original fact time uses an explicit ISO time or the captured report time; legacy sources without a payload time retain the native creation-time fallback. Attribution uses SDK author precedence and tracker settings. The owner's admission may change while its original Test provenance remains intact. Native comments record owner changes in the same conditional mutation. Native reads select complete domain fields and the source revision metadata without enumerating child records. They contain record ids rather than repeated untrusted fact bodies.

Stable ids hash intent with an optional caller operation identity. Every immutable source envelope includes its native identity and owner scope, so the SDK unique-key guard cannot conflate identical facts or explanations from separate investigations. Prefix normalization follows tracker settings. Exact repeated intent is idempotent; a separate repeated event needs a separate operation identity. Both original data and prediction equality remain byte-sensitive. Reusable keys, values, author/citation ids and native item identities are returned byte-exact. All structured strings, including statements, reasons and acquisition descriptions, stay exact. Native display titles alone use human text escaping. Scoped host renderers serialize JSON/TOON control bytes reversibly rather than rewriting identity data; decoded ANSI, quotes, newlines and Unicode round-trip into observe. Nested data is always structured output, never an executable prompt.

## Matrix and conclusion

For each hypothesis, every admitted observation matching a prediction key but differing in value is an eliminating witness. Disputed/withdrawn facts never eliminate. An observation of an unrelated key never eliminates. Multiple contradictory admitted facts remain visible: the package does not select a convenient truth.

A hypothesis with witnesses is eliminated. With no witnesses it is unknown when any prediction key has no admitted observation, or it has no predictions. Otherwise it is viable. Unknown and viable both survive; missing facts never remove a possible cause. Withdrawal recomputes from all remaining admissions, restoring exactly the hypotheses that have no remaining witness.

Conclusion validates its captured snapshot through the same conditional helper as every other mutation. The selected cause must survive, and every other viable/unknown explanation must be explicitly acknowledged by id. A conclusion is an investigator decision, not causal proof. Its basis revision becomes stale after any later hypothesis or observation change.

## Next request

Consider unobserved prediction keys on surviving explanations. For each key, group explanations by predicted exact value. Count unordered pairs with different declared values; unspecified explanations remain in a separate list and do not count as a proven split. Choose the highest pair count, then the shortest UTF-8 key, then English lexical order. The result shows each predicted value group and its hypothesis ids. A zero-score candidate is not a discriminating request, so return null when none exist. Length is a deterministic observation-size proxy, not a measured execution cost.

## Conditional mutation and recovery

Every writing path builds its complete batch in memory through the shared admission helper. Source preparation never creates a Test or Question. Initial SDK schema registration is package setup; incompatible existing field definitions are checked before setup writes. Once fields are installed, opens never silently recreate removed native types. The investigation's conditional owner update is the first item mutation, followed by required native creations in the same SDK batch. A new investigation stores its envelope in its native creation.

The helper captures native schema, field and status registries with the owner and all declared sources. SDK field projections follow the captured registry, including schema-removal races. Authoritative field reads explicitly disable SDK row and token limits so a compacted string summary can never be parsed as a domain record; packet budgets apply only after complete source reads. The same signatures and every captured item version are checked before decisions, before preview/commit, and inside the SDK `prepared` transition. Existing sources stay leased and fenced through the batch. Leases are acquired after the SDK workspace writer to avoid recovery lock inversion. No path refreshes its captured preconditions in a retry loop.

`previewItemMutations` validates the exact ordered batch with the SDK's native coordinator in a disposable tracker. The identical mutation list is then passed to `commitItemMutations`. Missing native types, required fields and invalid metadata therefore fail before any source-tracker item or history write, including compensation history. SDK 2026.10.26 supplies the managed dependency-tree exclusion from upstream PR 1595; the earlier published SDK preview cannot support normal managed executable links.

Preview receipts retain their unresolved constraints in package attempt lineage. Concurrent tracker/schema changes are revalidated under the commit fences; native extension mutation guards and hooks remain live during the actual SDK commit. A real guard test proves they are skipped by preview and enforced by commit. Derived managed dependencies are runtime installation assets rather than authoritative schema/item storage. Unexpected runtime hook or I/O failures still use the SDK's append-only compensation contract; preview is not an attestation of those runtime effects.

Replay succeeds without a write only when the canonical stored declaration matches the requested statement, predictions and provenance. A matching id with changed data returns `declaration_mismatch`, with stored/requested digests and a repair remedy. Prediction order does not change intent, including byte-distinct Unicode keys that collate equally: canonical sorting uses a byte tie-break. Mutable withdrawal state does not silently re-admit a repeated original fact.

Stable native ids hash intent and scope. Transaction ids additionally bind captured item/schema preconditions and fresh invocation entropy, preventing a changed initialization revision from colliding with an old journal or adopting a peer's terminal journal. Recovery reads current native state and constructs a new plan. Never-created sources from an explicitly interrupted owner-first batch can be completed; identities with native deletion history are not resurrected. Missing or invalid sources never eliminate while recovery is pending.

Package recovery lineage lives in `runtime/pm-hypothesis`, using public SDK lease, file-read and atomic-write primitives. It contains transaction ids, intent/precondition digests and constraint receipts, never frozen mutation payloads or absolute paths. Only validated plans are recorded. A fresh plan supersedes matching pending attempts; a verified no-op marks them satisfied from current native state. Native domain data and history remain SDK item records. The SDK still lacks public journal status/abandon/replan methods (pm-cli#1597), so supersession is package bookkeeping; SDK journals are never read or rewritten.

## Current source validity

A read obtains the owner and every source through projected public SDK reads, including deleted identities. It then leases and revalidates one coherent owner/source snapshot (or revalidates injected remote reads) before deriving output. Observation validity requires the canonical native identity, native Test type, the investigation parent, an allowed payload schema, matching key/value and who/when/how/evidence provenance, matching active admission status, and no native closure/withdrawal or terminal status role. Status aliases, cancellation, default terminal roles and custom terminal roles are resolved through the current SDK status registry, so a schema role edit changes usability even when the native source revision is unchanged. Legitimate owner withdrawal keeps the original source provenance but makes the fact inactive. Hypotheses require native Question type, canonical identity, parent and the exact sealed prediction envelope.

Invalid observations supply no witnesses. Invalid hypotheses remain visible as `invalid` rows and never participate in next-request splits. Active invalid sources prevent a new conclusion; invalid withdrawn facts remain historical context. `show` returns all issues, raw owner observations, the next request and the recorded decision, with `conclusionValid` and `invalidConclusion` distinguishing unusable support. Resume carries issue rows and marks invalid decisions stale. Matrix/resume receipts bound issue details separately and name the complete `show` command for every omitted field.

Tests include fresh-record combined owner/source edits (no pre-created fixture source), a 1,312-schedule ordered boundary-pair matrix, native SDK step crashes/interleavings and model-based sequences seeded with 24301, 12648430 and 720251025. The reference model independently checks current native images, all decision surfaces, append-only histories, exact live item ids and byte-identical refusals after each command. Peer edits cover type, parent, payload, provenance, deletion and owner revisions at all seven package boundaries. Additional state machines seeded with 20261026, 1597 and 5006 perform 195 state checks, 48 byte-identical refusals and nine SDK/JSON/TOON round trips. They include schema type removal/renaming, field removal, custom terminal roles, withdrawn/canceled sources, declaration replays and existing conclusions. Complete matrix, request, observations and conclusion validity are compared with an independent reference through one unbounded show snapshot per step; bounded resume packets are checked periodically. The separate round-trip property checks 82 key/value cases across JSON and TOON, plus both native CLI formats. Recovery checks all 68 journal-boundary/edit combinations for six mutating paths. Pure elimination equivalence is also checked over 100 random sets persisted with real native SDK records.

## Budgets and limits

Matrices contain all witnesses. Resume rows prioritize current source issues, the next request, any conclusion, survivors with open predictions, then concise eliminating witness rows in rounds, so one witness for each eliminated explanation precedes additional witnesses. A deterministic prefix fits the requested budget. The receipt distinguishes complete source reads from withheld output rows and names the actual `hypothesis show <id> --json` command. The unbounded show path returns every matrix row, every observation and the complete conclusion, so even an omitted long conclusion can be recovered. Empty output cannot silently assert complete data. Token estimation is the ceiling of the larger lossless host JSON/TOON transport representation divided by four, including the receipt and its own counter. It is an estimate, not a model tokenizer.

Text inputs have a limit of 8,192 characters and each hypothesis has 1–1,000 distinct predictions. Budgets range from 1 to 1,000,000 estimated tokens; extremely small budgets refuse. A conflicting invocation never refreshes its preconditions; a retry is a new invocation. Matrix work is proportional to declared predictions times admitted observations; the atomic owner favors compact incident sets rather than unbounded event streams.

Optional evidence citations are retained as provenance with a host-availability receipt; their contents and freshness are owned by pm-evidence. The package never imports it or executes its commands. No confidence estimate, model output or missing evidence constitutes an eliminating fact.

## Backend boundary

The SDK exposes host-bound reads and a workspace transaction service, but the item mutation helper takes a filesystem tracker root and lock-held field match. That SDK gap prevents an honest claim of conditional Postgres/MCP mutation conformance. This package certifies filesystem trackers with and without Git, supports injected host read clients, and never bypasses SDK history or writes raw storage. Remote mutation certification must wait for the host's authoritative conditional item capability; the package must refuse unsupported transports before effects when such transports are supplied. No remote backend is accessed by this implementation or its proofs.
